## 評価されている理由・印象的だった点

検索結果から確認できた紹介記事の要約によると、このサイトは「ラグジュアリーブランドの実際のイベント空間を、単なる商品カタログではなく“もう一度歩ける展示室”としてWebに翻訳した」点が評価されています。

- Cartierのリアルなパビリオンが「アルコーブ(壁の凹み=小部屋)」という建築コンセプトで作られており、それをそのままデジタル側でも「1体験=1アルコーブ」という単位に翻訳している構成
- スクロールが単なる「下にページ送り」ではなく「部屋から部屋へ移動する」体験として設計されている点(スクロール量がカメラの移動量に変換される)
- 各アルコーブが漂う地平線・揺れる水面・映り込む鏡といった、ジュエリー(時計)そのものよりも“その時計が置かれている静かな世界”を作り込むことで、プロダクトショットにはない没入感を出している
- 音楽(Mooders制作のスコア)がBGMとしてではなく「体験を貫くナレーションの層」として設計され、視覚と聴覚が同期している
- クリックやホバーなど「隠しジェスチャー」に応答する仕掛けがあり、ただ眺めるだけでなく“触って確かめる”楽しさが評価軸として紹介されている

## 使われている技術・ライブラリの推測

検索結果の要約(Awwwardsの受賞ページ情報、Immersive Gardenの制作実績紹介、同種のThree.js作品を紹介する記事の要約)から、以下の技術的特徴が使われていると推測しました。

- **Three.js(WebGL)** — 6つの3Dアルコーブそれぞれを個別のシーン/環境として描画。水面・地平線・鏡面反射などのマテリアル表現にGLSLシェーダーを組み合わせていると推測されます
- **Blender** — 時計や空間のアセット(3Dモデル)の制作に使用
- **GSAP + Lenis** — 「モーションとスクロールを同じ神経系でつなぐ」と紹介されており、慣性のあるスムーススクロール(Lenis)と、それに同期したタイムライン制御(GSAP)を組み合わせていると推測されます
- **Web Audio API** — Mooders制作の音楽スコアを、単なるBGMではなく体験の進行(部屋の切り替わりなど)と同期させるナレーション層として使用
- **隠しジェスチャー** — ホバー・クリック・ドラッグなど、明示的なUIとして提示されない操作に対してオブジェクトや空間が反応する仕掛け

このデモでは、GSAPやLenisを使わず**Three.js(WebGLの描画部分)のみ**を外部ライブラリとして使い、スクロール連動のカメラワークや慣性のあるスムーススクロールは依存ゼロのバニラJavaScript(`scroll`イベント + 指数減衰によるlerp)で実装しています。「GSAP+Lenisが内部でやっていること」は数十行のバニラJSでも体感できることを示すためです。また、音楽スコアの代わりに、クリック時に鳴る短いチャイム音をWeb Audio APIのオシレーターでその場で合成しており、外部の音声ファイルは一切使用していません。

## 再現コードの仕組みの解説

`index.html` 1ファイルに CSS・JavaScript をすべてインラインで記述し、3D描画のみ `vendor/three.module.min.js` を読み込んでいます。実装は大きく5つの仕組みに分かれており、それぞれ他プロジェクトにもそのままコピーできます。

### 1. 「部屋(アルコーブ)」をデータ配列として持つ設計

```js
const ALCOVES = [
  { title: "The Amber Hour", roman: "I", desc: "…", fog: 0x2a1a0c, floor: 0xd8b46a, gem: 0xffb066, side: 1 },
  // ... 全6部屋
];
const ROOM_DEPTH = 16;
```

各部屋はワールド座標のZ軸方向に `ROOM_DEPTH` ずつ離して並べているだけで、部屋の内容(色・タイトル・説明文)はすべてこの配列に集約しています。部屋を増やしたり配色を変えたりしたいときは、この配列を編集するだけで済むようにしているのがポイントです。

### 2. スクロール→「部屋の連続的な進行度」への変換(GSAP+Lenis不使用)

```js
function updateScrollProgress() {
  const max = document.documentElement.scrollHeight - innerHeight;
  const t = max > 0 ? document.documentElement.scrollTop / max : 0;
  scrollProgress = t * (roomCount - 1); // 0 〜 5 の連続値
}
```

毎フレーム、この目標値 `scrollProgress` に対して現在値 `smoothProgress` を指数減衰で追従させています。

```js
smoothProgress += (scrollProgress - smoothProgress) * (1 - Math.pow(0.001, dt));
```

これはLenisのような慣性スクロールライブラリが内部でやっていることとほぼ同じで、「目標値に瞬時にジャンプせず、フレームレートに依存しない速度で徐々に追いつく」処理です。`dt`(前フレームからの経過時間)を使っているため、60fpsでも30fpsでも同じ体感速度になります。

#### つまずいたポイント: 「最後の部屋にたどり着けない」バグ

指数減衰は理論上どれだけ待っても目標値に**完全には一致しません**(浮動小数点の丸めで最終的にほぼ一致はしますが、時間がかかります)。最初の実装では「現在の部屋インデックス」を `Math.floor(smoothProgress)` で求めていたため、一番奥の部屋(インデックス5)にスクロールしても `smoothProgress` が `4.999999…` にとどまり続け、`floor()` が永久に4を返してしまう=**最後の部屋のキャプションやインタラクションが有効にならない**という不具合が発生しました。

対策として、用途によって丸め方を使い分けています。

- カメラを2部屋間で滑らかにブレンドするための「基準の部屋」は `Math.floor()` のまま(`frac = smoothProgress - blendIdx` で補間比率を作るため)
- 「今どの部屋にいるか」を判定するキャプション表示・ホバー判定・ドットのハイライトには `Math.round()` を使う

```js
const blendIdx = THREE.MathUtils.clamp(Math.floor(smoothProgress), 0, roomCount - 2);
const idx = THREE.MathUtils.clamp(Math.round(smoothProgress), 0, roomCount - 1); // 現在の部屋
```

四捨五入なら `4.9999…` は `5` に丸まるため、最後の部屋も正しく「現在の部屋」として認識されます。スクロール連動の実装で「最後だけ挙動がおかしい」という不具合が出たときは、このような減衰・補間の端点処理を疑ってみてください。

### 3. 疑似的な水鏡フロア(GLSLシェーダー)

本物のプラナーリフレクション(反転カメラでシーンをもう一度描画してテクスチャに焼く手法)はコストが高いため、このデモでは軽量な2段構えの表現にしています。

1. **床のジオメトリを波打たせるシェーダー** — 頂点シェーダーでサイン波を重ねて床面をゆっくり揺らし、フラグメントシェーダーで縁が明るくなるフレネル風の着色をしています。
2. **オブジェクトそのものを上下反転して床下に薄く重ねる** — 「本物の鏡」ではなく「反転コピー+半透明+フォグに沈める」ことで、反射があるように見せています。

```js
const mirrored = makeGem(cfg.gem);
mirrored.scale.y = -1;
mirrored.position.y = -1.9 - 1.3;
mirrored.traverse((o) => { if (o.material) { o.material = o.material.clone(); o.material.opacity = .28; } });
```

さらに、クリックした位置に波紋を広げる仕組みも同じシェーダーの中に組み込んでいます。JavaScript側ではクリック時に「位置」と「開始時刻」だけを `uRipples` というuniform配列に書き込み、実際の波紋の減衰・広がりの計算はすべてGLSL側(頂点シェーダー内の `for` ループ)で行っています。JavaScriptで波紋オブジェクトを何個も管理する必要がなく、GPU側で並列に計算できるのが利点です。

### 4. 隠しジェスチャー(ホバー・クリックへの反応)

Three.jsの `Raycaster` を使い、現在いる部屋の宝飾オブジェクトにマウスカーソルが重なっているかを毎フレーム判定しています。

```js
raycaster.setFromCamera({ x: pointer.tx, y: -pointer.ty }, camera);
const hover = raycaster.intersectObject(room.gem, true).length > 0;
```

ホバー中は自転速度と浮遊の振幅を上げ、カスタムカーソルを大きく変形させることで「オブジェクトが反応している」ことを伝えています。クリックすると、Web Audioのオシレーターでチャイム音を鳴らしつつ、床の波紋uniformを更新します。何もない場所を漫然と眺めているだけでは気づきにくく、触ってみて初めて発見できる、という「隠しジェスチャー」の考え方をシンプルな形で再現しています。

### 5. カスタムカーソル

`mix-blend-mode: difference` を使った丸いカーソル要素をJavaScriptで座標追従させ、宝飾オブジェクトにホバーしているときだけ大きく変形させています。背景色に関わらず視認性を保てるのが `difference` ブレンドモードの利点です。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` と `vendor/three.module.min.js` を、自分のプロジェクトの好きな場所にそのままコピーします(フォルダ構成を保ってください)。
2. `ALCOVES` 配列(ファイル先頭付近)を書き換えて、部屋数・タイトル・説明文・配色を自分のプロジェクト用に差し替えます。部屋を増減させても、スクロール量の計算(`roomCount`)は自動で追従します。
3. 宝飾オブジェクトの形を変えたい場合は `makeGem()` 関数内のジオメトリ(`IcosahedronGeometry` や `TorusGeometry` など)を、好きなThree.jsのジオメトリや読み込んだ3Dモデルに差し替えるだけで、慣性の効いた自転・浮遊・ホバー反応・疑似反射の仕組みはそのまま使えます。
4. チャイム音の音程を変えたい場合は `playChime()` 内の `base` の値や倍音の配列(`[1, 1.5, 2.01]`)を調整してください。
5. `file://` で直接開くとブラウザによっては `type="importmap"` や `type="module"` が制限される場合があるため、`npx serve` や `python3 -m http.server` などの簡易サーバー経由で開くことをおすすめします。

### vendor フォルダについて

`vendor/three.module.min.js` は、npm公式レジストリで配布されているMITライセンスのオープンソースライブラリ(Three.js)をそのまま同梱したものです。対象サイトの著作物ではなく、誰でも自由に利用できるライブラリなので、自分のプロジェクトでもそのまま使えます。バージョンを更新したい場合は [three.js](https://www.npmjs.com/package/three) のnpmパッケージを取得し直してください。
