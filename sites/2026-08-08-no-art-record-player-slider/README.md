# VINYL DECK — レコードプレイヤー風コーンフロースライダー & 生きているギャラリー 再現デモ

## 参照元サイト

- **サイト名**: No Art
- **URL**: https://www.noartmusic.com/ (関連の制作事例紹介: https://www.weareboring.nl/en/work/no-art )
- **受賞歴**: Awwwards *Site of the Day*(2026年8月7日)。あわせて Developer Award(開発面での評価)も受賞しています。No Art はアムステルダム発の音楽・アートフェスティバル/レーベルで、そのグローバルな世界観をインタラクティブなストーリーテリングとして体験させるサイトです。

> **本フォルダのコードは学習目的のオリジナル実装です。** 参照元サイトの実際のソースコード(HTML/CSS/JS)・画像・映像・楽曲・アーティスト名・テキストコピーは一切取得・参照・複製していません。また、このセッションのネットワーク環境では `noartmusic.com` ・ `weareboring.nl` ・ `awwwards.com` 本体への直接アクセスがネットワークポリシーでブロックされていたため、実サイトを直接閲覧してはいません。検索結果に表示された紹介記事の要約(「レーベルページにレコードプレイヤー風のスライダーがあり、GSAPで動きを付けている」「フェスティバルの写真が生き生きと動くギャラリーがある」という趣旨の説明)だけを手がかりに、見た目・文言・コードすべてをゼロから独自に設計・実装しています。レコードのタイトル・アーティスト名・写真のキャプションなどはすべて架空のダミーです。

## 評価されている理由・印象的だった点

検索結果から確認できた紹介文によると、No Art のサイトは「フェスティバル/レーベルという題材そのものを、サイトの操作感に落とし込んでいる」点が評価されています。

- レーベルのページに、実物のレコードプレイヤーを操作しているかのような「ディスクを選んで再生する」スライダーがあり、単なる画像カルーセルではなく「音楽レーベルらしい操作体験」になっている
- フェスティバルの写真を並べたギャラリーが、静止画のままではなく生き生きと動く演出を持っており、「会場の熱気」がサイトの動きとして表現されている
- これらのインタラクションに GSAP が使われ、サイト全体が「フェスティバルのように賑やかで生き生きとした」印象を作っている、と紹介されている
- Awwwards の Site of the Day に加えて Developer Award も受賞しており、見た目の演出だけでなく実装面の作り込みも評価されている

## 使われている技術・ライブラリの推測

検索結果(紹介記事の要約)から、以下がうかがえます。

- **GSAP** — レコードプレイヤー風スライダーやギャラリーの動きに使われる定番のアニメーションライブラリ
- 一般的なこの手のサイトの実装パターンから類推すると、横方向のドラッグ操作をアニメーション値に変換する仕組み(スライダー)と、ホバー/スクロールをきっかけに要素を「生きているように」動かす仕組み(ギャラリー)の2つが核になっていると考えられます

このデモでは、GSAP を一切使わず、**依存ゼロのバニラJavaScript**で「同じ体験の仕組み」を再現しています。GSAPが行っている「値をなめらかに目標値へ近づける」処理を、`requestAnimationFrame` ループの中で自分で書いた線形補間(lerp)に分解しました。

## 再現コードの仕組みの解説

`index.html` 1ファイルに CSS・JavaScript をすべてインラインで記述しています。実装は、それぞれ独立して他プロジェクトにもコピーできる2つの関数にまとめています。

1. **`initRecordSlider(root, records)` — レコードプレイヤー風のコーンフロースライダー**
   - レコード盤(`.disc-item`)を「選択中のインデックスとの距離」で並べる、古典的なコーンフロー(coverflow)の数式を使っています。距離 `offset = i - dragIndex` に対して、`translateX = offset × 間隔`、`rotateY = offset × -35度`、`scale = 1 − |offset| × 0.16` という具合に、中央から離れるほど小さく・斜めに・薄くなるよう計算し、これを `disc-item` の `transform` に毎フレーム書き込んでいます。
   - ドラッグは Pointer Events(`pointerdown`/`pointermove`/`pointerup`)で座標差分を取り、「130px動いたらインデックスが1進む」という比率で `dragIndex`(小数を許す連続値)に変換します。指を離した瞬間に `Math.round(dragIndex)` で最も近い整数インデックスへスナップします。
   - 「再生中は盤とラベルが回転する」演出は、CSSの `@keyframes spin` を常時セットしつつ `animation-play-state` を `paused`/`running` でJSから切り替えるだけの単純な仕組みです。実際の音声は再生せず、視覚的な仕組みのみを再現しています。
   - トーンアーム(`.tonearm`)は `transform-origin` を右端寄りに設定した棒を `rotate()` させているだけです。再生中クラス `is-playing` が付くと `rotate(-32deg)` から `rotate(-4deg)` へ `transition` でなめらかに「盤の上に降りる」ように見せています。

2. **`initAliveGallery(container, photos)` — 生きているフェスティバルギャラリー**
   - 各タイルには、何もしなくても常に微小に上下する「呼吸するような」動き(idle float)を持たせています。`Math.sin(経過時間 / 1400 + phase)` でタイルごとに位相 `phase` をずらしたサイン波を使い、全タイルが同じタイミングで揺れて不自然に見えないようにしています。
   - カーソルを乗せると、カーソル位置(タイル中心からの相対位置 `-0.5〜0.5`)から3D傾き(`rotateX` / `rotateY`)の目標値を計算します。目標値へは即座にジャンプさせず、`現在値 += (目標値 − 現在値) × 0.12` という lerp を毎フレーム適用することで、素早いマウス移動にも滑らかに追従する「柔らかい」傾きになります。
   - 傾きと同時に、`<canvas>` に描いた粒子(グレイン)オーバーレイを `mix-blend-mode: overlay` でフェードインさせ、`filter: saturate() brightness()` で彩度・明るさも持ち上げることで、「写真が息を吹き返す」ような質感を出しています。粒子はランダムな座標に小さな矩形を90個描画するだけの軽量な実装です。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-08-no-art-record-player-slider
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. レコードの枚数・タイトル・アーティスト名・色は、スクリプト末尾の `RECORDS` 配列を書き換えるだけで変更できます。要素数を増減しても `initRecordSlider()` が自動的に対応します。
4. ギャラリー写真の枚数・タイトル・キャプション・背景グラデーションは、同じく `PHOTOS` 配列を編集するだけで反映されます。実際の写真を使いたい場合は `.gallery-visual` に `background-image` を追加してください(`--gi-bg` のグラデーションはそのまま下地として残せます)。
5. スライダーの間隔・傾き具合を変えたい場合は `initRecordSlider()` 内の `layout()` 関数にある `spacing`(間隔px)・`rotateY` の係数(`-35`)・`scale` の係数(`0.16`)を調整してください。
6. ギャラリーの傾きの強さ・追従の重さは `initAliveGallery()` 内の `px * 18` / `py * 18`(傾きの最大角度)と、lerp係数 `0.12`(大きいほど機敏、小さいほど重い)を変更してください。
7. 配色を変えたい場合は `:root` の `--bg` / `--ink` / `--accent` を書き換えるだけで、レコードのラベル色(`RECORDS` 内 `color`)以外は全体に反映されます。

## つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では `noartmusic.com` ・ `weareboring.nl` ・ `awwwards.com` への直接アクセスがネットワークポリシーでブロックされていました。そのため検索結果の要約情報のみを根拠に設計しており、実サイトの正確なレイアウト・配色・レコードの並べ方までは確認できていません。このデモは「公開情報から読み取れる範囲での解釈による再現」であり、実サイトの完全なコピーではありません。
- **`id` の重複によるバグ**: 実装時に `<section id="gallery">` と、その中の実際のグリッド要素 `<div id="gallery">` で同じ `id` を使ってしまい、`document.getElementById('gallery')` が意図しない `<section>` 要素(グリッドのCSSを持たない要素)を返してしまうバグがありました。結果としてギャラリーが横に並ばず縦に1列で積み重なって表示されてしまい、Playwrightで実際にスクリーンショットを撮って初めて発覚しました。`id` はページ内で一意にする、というHTMLの基本を、アンカーリンク用の外側セクションと内側のスクリプト対象要素とで安易に共有しないことで対処しました(外側は `#gallery-section` に変更)。
- **コーンフローの`z-index`管理**: 中央のディスクが常に一番手前に来るよう、`z-index` を「中心からの距離が近いほど大きい値」になるよう計算する必要がありました。単純に配列のインデックス順で `z-index` を振ると、ドラッグ中に手前・奥の前後関係が入れ替わってしまうため、`Math.round((1 - Math.min(距離, 5)) * 100)` という式で距離ベースの値を毎フレーム再計算しています。
