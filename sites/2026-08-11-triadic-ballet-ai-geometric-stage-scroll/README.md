## 再現コードの仕組みの解説

`index.html` 1ファイルに CSS・JavaScript をすべてインラインで記述しています。実装は、他のプロジェクトにもそのままコピーできる小さな関数の集まりとして書かれています。

1. **`sampleGradient(stops, t)` — 複数の色を跨ぐグラデーションの補間**
   `[[r,g,b], [r,g,b], [r,g,b]]` のような色の配列(このデモでは黄・薔薇色・黒の3色)を渡すと、`t`(0〜1)の位置に応じて隣り合う2色の間を線形補間して返します。幕がいくつに増減しても(4幕・5幕にしても)配列に色を追加するだけで動く、汎用的な実装です。

2. **`createScrollStageDriver(sections, onUpdate)` — スクロール→(幕番号・幕内進捗・全体進捗)への変換**
   `#hero` と `.act` の全セクション要素を渡すと、毎フレーム `requestAnimationFrame` の中で `window.scrollY` から「生の進捗(0〜1)」を計算し、それを毎回ジャンプさせず `smoothT = lerp(smoothT, targetT, 0.09)` のようにわずかずつ追従させています。これにより、スクロールホイールのようにガクガクした入力でも、色やダンサーの動きは常に滑らかになります。得られた `smoothT` から「今何幕目にいるか(`actIndex`)」「その幕の中でどこまで進んだか(`actProgress`)」を割り出し、コールバックに渡します。

3. **`poseDancer(dancer, globalT)` — ダンサーの姿勢を幕間でモーフィングさせる**
   各幕の「らしさ」を、**回転角・左右の腕の開き具合・全体スケール**というたった4つの数値(`DANCER_POSES` 配列)だけで表現しています。第1幕は腕を軽く開いた回転少なめのポーズ、第2幕は腕を大きく左右に広げた荘厳なポーズ、第3幕は静止に近い直立ポーズ、というように定義し、幕と幕の間はここでも線形補間でなめらかに繋いでいます。

4. **舞台照明とダンサーの配色を同期させる**
   `STAGE_COLOR_STOPS`(舞台の背景色)と `COSTUME_COLOR_STOPS`(ダンサーのコスチューム色)という2つの色配列を用意し、同じ `colorT` の値でどちらも `sampleGradient()` にかけています。これにより「舞台が暗くなるにつれてダンサーの衣装も金色から銀白色へ変わる」という、単一の進捗値からすべての色を導く一貫した仕組みになっています。文字色も舞台の明度(輝度)を計算して自動的に黒/白へ切り替えており(WCAGの簡易的な輝度式を使用)、どの幕でも可読性が保たれます。

5. **`initActNav(navEl, sections)` — 幕番号ナビ(I / II / III)**
   ボタンをJSで自動生成し、クリックすると対応するセクションへ `scrollIntoView({behavior:"smooth"})` します。現在の幕にはCSSクラス `is-active` が付き、`opacity` と `transform:scale()` でハイライトされます。ナビとヘッダーには `mix-blend-mode:difference` を使っており、背景色がどれだけ暗く/明るくなっても、JS側で個別に色を切り替えなくても常にコントラストが保たれます。

6. **`initWordReveal(root)` — 単語単位のスクロールリビール**
   各見出し・段落を `<span class="word"><span class="word-inner">単語</span></span>` の入れ子で囲み、外側の `.word` に `overflow:hidden`、内側の `.word-inner` に `transform:translateY(110%)` の初期状態を与えています。`IntersectionObserver` でセクションが画面に入ったことを検知すると `is-in` クラスを付与し、CSSの `transition` だけで「下からせり上がるように文字が現れる」演出を実現しています。

## つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では、対象サイトのドメイン・`awwwards.com`・`cssdesignawards.com` など、調査に使いたかった外部サイトへの直接アクセスがすべてネットワークポリシーでブロックされていました(`EGRESS_BLOCKED`)。そのため、Web検索結果に表示された紹介文のみを根拠に設計しており、実サイトの正確なレイアウトや配色、実際のAI画像・アニメーションの中身までは確認できていません。このデモは「公開情報から読み取れる範囲での解釈による再現」であり、実サイトの完全な再現ではないことにご留意ください。
- **IntersectionObserverの初期化タイミング**: ページ読み込み直後にすぐ `IntersectionObserver` を設置すると、フォントの適用などでレイアウトが確定する前にセクションの高さ・位置が一時的に不正確な値になり、本来まだ画面外にあるはずの幕が「交差している」と誤判定されることがありました。このデモの `initWordReveal` は一度 `is-in` が付くと外さない一方向の実装のため、誤判定が起きるとその幕の文字が最初から見えてしまいます。`requestAnimationFrame` を2回連続でネストして呼び、レイアウトが確定してから `initWordReveal()` を実行することで回避しました。
- **文字色の同期漏れ**: 当初、舞台が暗くなったときの文字色切り替えを `document.body.style.color` へ直接代入していたところ、`::selection`(テキスト選択時の配色)など別の場所で参照している `var(--fg)` が更新されず、選択時の配色だけ暗いままになる不整合が起きました。`body.style.color` を直接書き換えるのではなく、ルート要素の CSSカスタムプロパティ `--fg` 自体を1箇所で更新するように直したことで、参照している全ての箇所が自動的に追従するようになりました。
- **固定ナビが本文と重なる**: 幕番号ナビ(I/II/III)を画面右の垂直中央に固定していたところ、右寄せになる幕(偶数番目のセクション)の見出しテキストと位置が重なってしまいました。ナビを画面右下に固定する配置に変更し、本文の見出しが表示される垂直中央のエリアを避けることで解決しました。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-11-triadic-ballet-ai-geometric-stage-scroll
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. 幕を増減・変更したい場合は、`<section class="act" data-act="...">` を追加/削除し、対応する `STAGE_COLOR_STOPS` / `COSTUME_COLOR_STOPS` / `DANCER_POSES` 配列にも同じ数だけ色・ポーズを追加します。3つの配列の要素数を揃えるだけで、`sampleGradient()` と `poseDancer()` は自動的に新しい幕数に対応します。
4. なめらかさを変えたい場合は `createScrollStageDriver()` 内の `SMOOTHING`(0〜1)を調整します。値を大きくするほどキビキビと、小さくするほどゆったりと舞台色・ダンサーが追従します。
5. 見出し・本文のスクロールリビールを別の要素にも適用したい場合は、対象の文字列を `<span class="reveal-line"><span class="word"><span class="word-inner">…</span></span></span>` で囲み、`initWordReveal()` が観察する対象(`.act, #hero` を指定している箇所)に該当セクションを含めるだけで動作します。
6. ダンサーの見た目を変えたい場合は `#dancer` 内のSVG(`polygon` / `ellipse` / `circle` / `rect`)を編集するだけで、色・姿勢の制御ロジック(`poseDancer()`)はそのまま使えます。
