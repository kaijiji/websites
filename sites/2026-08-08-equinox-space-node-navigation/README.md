## 評価されている理由・印象的だった点

検索結果の要約によると、Equinoxは「ダメージを受けた宇宙船の中を、AIを助けながら一人称視点で探索していくインタラクティブなストーリー体験」で、次のような点が評価されています。

- 派手なエフェクトの物量ではなく、**カメラワーク・サウンド・間(タイミング)でシネマティックな質感を出す**演出方針(スペクタクル重視ではなく雰囲気重視、と紹介されている)
- ゲームからの影響を受けた**一人称視点の探索**によって、ブラウザ上のWeb体験でも高い没入感を生み出している
- **PC・スマートフォンの両方**に対応しており、タッチ操作でも指1本だけで最初から最後まで物語を体験できるよう設計されている
- 音声・環境音・少しずつ変化するBGMを使い、探索と謎解きが物語の進行と結びついている

この再現デモでは、上記の中でも特に「**固定された視点(ノード)の間をカメラが滑らかにドリー移動して繋いでいく**」という、一人称探索インタラクションの骨格部分にフォーカスして再現しています。

## 使われている技術・ライブラリの推測

検索結果からは、公式サイト自体が独自のゲームエンジンとThree.js(WebGL)を組み合わせて作られていると紹介されていました。具体的なコードは確認できていませんが、一般的なこの種の一人称WebGL探索サイトでは、次のような技術要素が使われることが多いと考えられます。

- **Three.js / WebGL** — 宇宙船内部・宇宙空間の3Dシーン描画
- **フリー移動ではなくノード(視点)ベースのカメラ制御** — プレイヤーが自由にカメラを動かせるのではなく、あらかじめ用意された視点(ノード)の間をアニメーションで繋ぐことで、狙った構図・ペース配分を保ったまま探索させる手法(アドベンチャーゲームの「地点間移動」に近い考え方)
- **Web Audio API によるアンビエントサウンド・ボイス** — 環境音や音楽が探索や謎解きの進行と連動
- **タッチ最適化された単一指インタラクション** — クリック/タップだけで全操作が完結するUI設計

このデモでは、**Three.jsを使わず、CSSの `perspective` + `preserve-3d` + `translate3d` だけで疑似3D空間とカメラドリーを再現**しています。「本格的な3Dライブラリがなくても、視点移動の気持ちよさの大部分はCSSだけで再現できる」ことを体験してもらう狙いです。

## 再現コードの仕組みの解説

`index.html` 1ファイルにCSS・JavaScriptをすべてインラインで記述しています(外部ライブラリへの依存なし)。中心となるのは `createSpaceNavigator(sceneEl, options)` という、他のプロジェクトにもそのままコピーして使える関数です。

### 1. 「カメラを動かす」のではなく「世界を逆向きに動かす」

```html
<div id="scene">   <!-- perspective: 900px を持つビューポート -->
  <div id="world">  <!-- transform-style: preserve-3d のカメラ本体 -->
    <div class="node" style="transform: translate3d(x, y, z)">...</div>
    ...
  </div>
</div>
```

各ノード(訪問地点)は `#world` の中に `translate3d(x, y, z)` で3D空間上の絶対座標として配置します。カメラを前に進めたいときは、カメラ自身の座標を動かすのではなく、**`#world` 全体を目的地とは逆方向に平行移動**させます。`perspective` が親の `#scene` に掛かっているため、この移動だけで「自分(カメラ)が奥へ進んでいく」ような自然な遠近感のあるドリー演出になります。

### 2. 指数減衰(lerp)による慣性のあるカメラワーク

```js
cam.x += (target.x - cam.x) * 0.045;
cam.z += (target.z - cam.z) * 0.045;
```

ノードをクリックすると `target` (目的地の座標)が即座に更新されますが、実際に描画に使う `cam` (現在のカメラ座標)は毎フレーム少しずつ `target` に近づいていくだけです。この「目標値との差分に係数を掛けて足し込む」処理を`requestAnimationFrame`ループで回し続けると、GSAPのようなアニメーションライブラリやCSS `transition` を使わなくても、**慣性のある重みを持ったカメラの滑走**が数行で作れます。値を大きくするほどキビキビ、小さくするほどゆったりした動きになります。

### 3. 星空のパララックス(視差)

星は `box-shadow` を数百個連結した文字列として1回だけ生成し、`border-radius:50%` の小さな円1個に貼り付けています(DOM要素を星の数だけ作らない軽量テクニック)。手前・中間・奥の3層を用意し、カメラ移動量に対して手前の層ほど大きい係数(`px * 0.05` など)で動かすことで、実際に奥行きがあるように錯覚させています。

### 4. 手前の透明な当たり判定に注意(3Dヒットテストの落とし穴)

実装中に見つかった実務的なハマりどころとして、`#world` は全画面を覆う「透明な平面」ですが、3D空間上ではノードのボタンより手前に来ることがあり、そのままだと**見えないはずの`#world`自身がクリックを奪ってしまう**現象が起きました。対策として `#world { pointer-events: none }` にしたうえで、実際に押させたい `.node-hit`(ボタン)だけに `pointer-events: auto` を明示しています。3D transformを使ったUIを自作するときに再利用できる典型的な対処法です。

### 5. アンビエントサウンド(Web Audio API)

実サイトの音源は使わず、`OscillatorNode` 2つ(周波数を少しだけずらしてビート＝うなりを作る)と、ゆっくりしたLFO(低周波発振)で音量を揺らすだけの擬似エンジン音をゼロから合成しています。ブラウザの自動再生ポリシーに従い、ユーザーが「AMBIENT」ボタンを押した後にのみ`AudioContext`を生成・再生します。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` をそのまま自分のプロジェクトにコピーします(外部ライブラリ不要)。
2. `<script>` 内の `NODES` 配列を書き換えて、自分のコンテンツ(ノードの座標・タイトル・本文)に差し替えます。

   ```js
   const NODES = [
     { id: 'a', x: 0,   y: 0,   z: 0,    title: '見出し1', text: '本文1' },
     { id: 'b', x: 500, y: -80, z: -700, title: '見出し2', text: '本文2' },
     // z はマイナスが「奥」。数百〜千数百px単位でずらすと奥行きが出ます。
   ];
   ```

3. `createSpaceNavigator(sceneEl, { nodes, onArrive })` はそのまま流用できる汎用部品です。`onArrive` コールバックの中で、パネル表示以外にも「画像を切り替える」「別のアニメーションを再生する」など好きな処理を追加できます。
4. コードから特定のノードへ移動させたい場合は `nav.goTo('ノードのid')` を呼び出すだけです(ボタン以外のUI、例えば目次メニューなどからも呼び出せます)。
5. 画面をドラッグすると視点を少しだけ左右上下に振れます(見渡し演出)。不要な場合は `pointerdown`/`pointermove` のイベントリスナー部分を削除してください。
