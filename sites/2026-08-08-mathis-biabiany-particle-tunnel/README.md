## 再現コードの仕組みの解説

`index.html` 1ファイルにCSS・JavaScriptをすべてインラインで記述しています。実装は、他のプロジェクトにそのままコピーできる小さな関数の集まりとして書かれています。

1. **`SHAPES` 配列 + `sampleShapeToPoints()` — 図形をパーティクルの「目標座標」に変換する**
   実サイトは実際の写真・作品画像を使っていますが、このデモは著作権に配慮し、Canvas 2Dで自前生成した4つの幾何学図形(リング・ダイヤモンド・波線・「3D」の文字)を使っています。`sampleShapeToPoints()` は、オフスクリーンのcanvasに図形を白色で描画し、一定間隔(`SAMPLE_CELL`px)でピクセルをスキャンして「不透明度が高い(=図形がある)場所」の座標を集めます。そこからランダムに(小さなジッターを加えながら)`PARTICLE_COUNT` 個を抽出することで、どの図形でも常に同じパーティクル数の点群を得られるようにしています。**実写真を使いたい場合は、`draw(ctx, w, h)` の中身を `ctx.drawImage(image, 0, 0, w, h)` に差し替えるだけで、同じ仕組みがそのまま使えます。**
2. **`createParticleSystem(gl, count)` — パーティクルの現在位置をGPUで計算する**
   各パーティクルは以下の属性(attribute)を持ちます。
   - `aStart` / `aEnd` … 現在表示中の図形 / 次に表示する図形での座標(モーフィングのたびに`setShapePair()`で差し替え)
   - `aRand` … 渦の角度・回転速度・弾け出す半径・パーティクルサイズをばらけさせるための乱数と、開始タイミングをずらす`stagger`用の乱数(`aRand.w`)
   毎フレーム、頂点シェーダー内で `uProgress`(0〜1の全体進行度)から、パーティクルごとに少しずつ開始時刻をずらした `local` 進行度を計算し、`bulge = sin(local_eased * π)` という1つの式で「0(静止)→1(最大に弾ける)→0(新しい図形に収束して静止)」という山なりのカーブを作っています。この `bulge` を、乱数から決めた角度で回転し続けるベクトル(`vec2(cos(angle), sin(angle))`)に掛け合わせることで、「外側へ弾け飛びながら渦を巻き、収束していく」というトンネル演出を実現しています。
3. **カラフルな発光パーティクル(フラグメントシェーダー)**
   `gl_PointCoord` を使って各パーティクルを円形にクリップし(`discard`)、中心が明るく縁がやわらかく減衰するアルファ値を計算します。色相(Hue)は `aRand.w` とトンネルの弾け具合(`bulge`)、経過時間から連続的に変化させ、`hsv2rgb()` でRGBに変換しています。`gl.blendFunc(gl.SRC_ALPHA, gl.ONE)` による加算合成(additive blending)で、重なったパーティクルほど明るく発光して見えるようにしています。
4. **クリック/タップでのトランジション制御**
   `startTransition(nextIdx)` が呼ばれると、現在の図形の点群を `aStart`、次の図形の点群を `aEnd` としてGPUバッファへアップロードし、`performance.now()` を基準にした経過時間で `uProgress` を0→1へ進めます。進行度が1に達した時点で「現在の図形」を次の図形に切り替えるだけで、次のトランジションの`aStart`にそのまま使えるようになっています(`aEnd`が新しい静止状態と一致するため、余分なリセット処理が不要)。
5. **マウス視差(パララックス)**
   マウス座標を`-1〜1`に正規化し、目標値へ毎フレーム少しずつ`lerp`で近づけた `uParallax` を頂点シェーダーに渡し、全パーティクルの位置にわずかなオフセットを加えることで、マウスを動かすとシーン全体がゆっくり追従するような奥行き感を出しています。

### つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では、`mathis-biabiany.fr` はもちろん `example.com` のような無害なテスト用ドメインへのアクセスすら `EGRESS_BLOCKED` としてネットワークポリシーでブロックされていました。そのため実サイトの正確なビジュアル(使用画像・配色・カメラワーク)は確認できておらず、検索結果のスニペット(受賞歴・使用技術タグ・Codrops記事の要約)だけを根拠に、技法の「仕組み」を解釈して再現しています。
- **図形ごとにパーティクル数が変わってしまう問題**: 単純に「白いピクセルの座標をすべて使う」実装にすると、図形によって候補点の数が大きく変わり、モーフィングの前後でパーティクル数が変わって不自然になります。候補点からランダムに `PARTICLE_COUNT` 個を**重複を許して**サンプリングし、重複した点にはごく小さなジッターを加えることで、この問題を解決しています。
- **トンネル演出の「弾けて戻る」動きを1つの式にまとめる**: 最初は「外へ弾ける」フェーズと「収束する」フェーズを別々のif分岐で実装しようとしましたが、境界で速度が不連続になりカクついてしまいました。`sin(easedProgress * π)` という1つの連続関数に置き換えることで、分岐なしに滑らかな山なりカーブが得られ、コードもシンプルになりました。
- **パーティクルごとの開始タイミングをずらす(stagger)と進行度の計算**: 全パーティクルが完全に同時に動くと機械的で単調になるため、`aRand.w`(0〜1の乱数)を使って開始タイミングを最大55%までずらしています。ただしそのままだと `uProgress` が1になっても一部のパーティクルが動き終わらない計算になってしまうため、`local = (uProgress - stagger) / (1 - stagger)` という式で「ずれた分だけ残り区間を引き伸ばして正規化」することで、`uProgress = 1` の時に必ず全パーティクルが `local = 1` (完全に新しい図形に収束した状態)になるようにしています。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-08-mathis-biabiany-particle-tunnel
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. 画面をクリック / タップすると、ランダムに選ばれた次の図形へパーティクルがトンネルを通ってモーフィングします。何もしなくても約4.6秒ごとに自動で切り替わります。下部のドットをクリックすると、その図形へ直接ジャンプできます。
4. **好きな図形やロゴに差し替えたい場合**は、`SHAPES` 配列の各 `draw(ctx, w, h)` 関数を書き換えてください。Canvas 2Dの通常の描画API(`fillRect` / `arc` / `fillText` など)がそのまま使えます。実写真・自分のロゴ画像を使いたい場合は `ctx.drawImage(image, 0, 0, w, h)` を呼ぶだけです(画像は事前に読み込んでおく必要があります)。
5. **パーティクル数を変えたい場合**は、ファイル冒頭の `PARTICLE_COUNT` を調整してください(値を大きくするほど密度が上がりますが、低スペック端末では重くなります)。
6. **トランジションの速さ**は `TRANSITION_MS`、**自動再生の間隔**は `AUTO_ADVANCE_MS` の数値(ミリ秒)を変更してください。
7. **既存のThree.js/WebGLプロジェクトにこの演出だけを移植したい場合**は、`VERTEX_SRC` / `FRAGMENT_SRC`(シェーダー文字列)と `createParticleSystem(gl, count)` 関数、および `sampleShapeToPoints()` をまとめてコピーし、自分のシーンの中で `system.setShapePair(startPoints, endPoints)` → 進行度を0〜1で渡しながら `system.draw({...})` を呼ぶ形で組み込めます。
8. 発光の色味を変えたい場合は、フラグメントシェーダー内の `hsv2rgb(vec3(vHue, 0.5, 1.0))` の彩度(第2引数)・明度(第3引数)や、頂点シェーダー内の `vHue` の計算式を調整してください。
