## 評価されている理由・印象的だった点

Web検索で得られた紹介文・レビュー要約をまとめると、このサイトは次の点が評価されています。

- **「祝賀ランディングページ」ではなく「生きたアーカイブ」のような佇まい** — スタジオの20年間で影響を受けた人・仕事・瞬間についての個人的なストーリーが、静かなトーンで綴られている
- **ゆったりとしたエディトリアルなペース配分** — 長文の語りをじっくり読ませるための余白と、控えめな2色構成の配色
- **のびやかな大きいタイポグラフィ** — 見出しのテキストが画面の主役になるレイアウト
- **DrawSVGによるパスの描画アニメーション** — スクロールして要素が画面に入るタイミングでSVGのラインが「描かれていく」演出
- **SplitTextによる見出しの演出** — 文字を分割することで、映画的("cinematic")な質感を持たせたテキストリビール
- インスピレーションを共有するよう促す招待(CTA)や、個人的なストーリーへの導線

このデモでは、上記のうち「**文字単位で立ち上がるSplitText風の見出しリビール**」「**スクロール量に連動してラインが少しずつ描かれるDrawSVG風のタイムライン**」「**タイムラインの各エントリーが画面中央に来たときにアクティブ化するスクロール連動の状態変化**」「**2色を基調にした余白の多いエディトリアルなレイアウト**」の4つを、GSAP等の外部ライブラリを一切使わず、バニラJS・CSS・SVGだけで再現しています。

## 使われている技術・ライブラリの推測

検索結果から確認できた情報として、以下が挙げられています。

- **Next.js + Tailwind CSS** — サイト全体のフレームワーク／スタイリング基盤(推測)
- **GSAP** — アニメーションエンジン。特に次の2つのプラグインが使われていると紹介されています
  - **DrawSVGPlugin** — スクロールで要素が画面に入るタイミングでSVGパスが描かれていく演出
  - **SplitText** — 見出しの文字・行を分割し、映画的な質感のテキストリビールを実現
- **最小限のプラグイン構成** — 「多くのプラグインを積まなくても強い印象を作れる」ことを示す実装だと紹介されており、装飾よりも「タイポグラフィ・アニメーション・ストーリーテリング」に絞った設計であることがうかがえます

このデモでは、GSAPを使わず、`getTotalLength()` / `stroke-dasharray` / `stroke-dashoffset` という素のSVG APIでDrawSVG相当の演出を、`IntersectionObserver` を使わない独自のスクロール位置計算でエントリーのアクティブ化を、CSSの `transition-delay` とカスタムプロパティ `--i` でSplitText相当の文字単位リビールを、それぞれゼロから実装しています。

## 再現コードの仕組みの解説

`index.html` 1ファイルにCSS・JavaScriptをすべてインラインで記述しています。実装は他のプロジェクトにもそのままコピーできる小さな関数の集まりです。

1. **`splitIntoChars(el)` — GSAP SplitTextの簡易自作版**
   要素のテキストをスペースで単語に分割し、各単語を `<span class="split-line">`(`overflow:hidden` で縦方向をマスク)で包んだ上で、単語内の1文字ずつをさらに `<span class="split-char">` で包みます。各文字には出現順の連番を `--i` というCSSカスタムプロパティとしてセットしておき、CSS側で `transition-delay: calc(var(--i,0) * 26ms)` を指定することで、JS側は「何文字目か」を割り振るだけで、あとはCSSのtransitionだけで文字が一文字ずつ少し遅れて立ち上がる「タイプライターならぬ“カーテンが上がる”ような」リビールが完成します。単語を `split-line` で包んで `overflow:hidden` にしているのは、単語の途中で改行された場合でも各行が独立してマスクされ、不自然な見切れが起きないようにするためです。

2. **`initDrawSVGOnScroll(path, track, onProgress)` — GSAP DrawSVGPluginの簡易自作版**
   SVGの `path.getTotalLength()` でパスの全長(この実装では単純な縦の直線なので `100`)を取得し、`stroke-dasharray` にその全長をセットします。これにより「線の実線部分の長さ＝全長、隙間の長さ＝0」という状態になり、見た目には普通の線に見えます。ここから `stroke-dashoffset` を全長分だけずらすと線が完全に隠れ、`dashoffset` を `0` に近づけていくと少しずつ線が現れる、という原理を利用しています。`scroll` イベント(`passive:true` + `requestAnimationFrame` で間引き)のたびに、タイムライン全体を包む `track` 要素の `getBoundingClientRect()` から「画面下端にトラック上端が来た瞬間を0、画面上端をトラック下端が抜けた瞬間を1」とする進行度 `progress` を計算し、`dashoffset = length * (1 - progress)` を毎フレーム更新します。これにより、スクロールするほど線が上から下へゆっくり伸びていく、DrawSVGらしい演出になります。

3. **`buildTimeline(container, items)` / `initRevealOnScroll(selector)` — エントリーごとのアクティブ化**
   年表データ(年・見出し・本文)からDOMを組み立て、各エントリーに丸い `dot` を配置します。`IntersectionObserver` で各エントリーが画面のしきい値(`threshold:0.4`、要素の4割が見えたら)を超えたかどうかを検知し、`is-active` クラスの付け外しを行うだけのシンプルな実装です。CSS側で `.tl-entry` の不透明度を通常時 `0.25`、アクティブ時 `1` に、`dot` の塗り色と大きさもアクティブ時に変化させることで、「今読んでいる項目だけがくっきり浮かび上がり、それ以外は控えめに沈む」というエディトリアルな読書体験を作っています。DrawSVGのライン進行(手順2)とは独立した仕組みですが、両方とも「スクロール位置」という同じ入力から動いているため、視覚的には線の到達位置とアクティブな項目が自然に連動して見えます。

4. **2色構成のCSSカスタムプロパティ設計**
   `--bg`(クリーム色の背景)と `--ink`(ほぼ黒の本文色)の2色だけを基準色とし、そこから `--ink-60` / `--ink-30` / `--ink-12` という不透明度違いの派生色を作ることで、アクセントカラーを増やさずに「本文・キャプション・区切り線・非アクティブ状態」の階調を表現しています。装飾色を足さずに済むため、タイポグラフィと余白そのものが主役になる、落ち着いたエディトリアルなトーンを保ちやすくなります。

### つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では `inspiring.nk.studio`・`www.nk.studio`・`awwwards.com`・`landing.love` はもちろん、動作確認用に立ち寄ろうとした無関係の既存サイト(`bruno-simon.com`)まで、外部ドメインへの直接アクセスがほぼ一律で `EGRESS_BLOCKED` として拒否されました。そのため本デモは、WebSearchのスニペットに含まれていた「DrawSVGでパスを描く」「SplitTextで映画的な見出しにする」「生きたアーカイブのような佇まい」「2色構成」というキーワードのみを手がかりに設計した解釈的な再現であり、実際のピクセル単位のレイアウトや正確なタイミングカーブは確認できていません。
- **`preserveAspectRatio="none"` のSVGでの `getTotalLength()`**: タイムラインのラインは `viewBox="0 0 64 100"` の小さな座標系で描き、CSSで `height:100%` を指定してタイムライン全体の実際の高さ(数百〜数千px)まで縦に引き伸ばしています。このとき `getTotalLength()` は**表示上のピクセル値ではなく、viewBox内のユーザー単位(この場合は`100`)**を返す点に注意が必要でした。`stroke-dasharray` / `stroke-dashoffset` も同じユーザー単位で解釈されるため、両者の単位さえ揃っていれば非等倍の引き伸ばし(`preserveAspectRatio="none"`)があっても線の描画進行は正しく動作します。単位の対応関係を意識しないと「実際のピクセル高さで全長を計算してしまい、線が描き終わらない／早く終わりすぎる」というバグが起きやすいポイントです。
- **`IntersectionObserver` のしきい値と「読んでいる項目」判定**: `threshold` を `1.0`(完全に画面内)にすると、縦長のテキストブロックが画面より大きい場合にいつまでもアクティブ化されない問題がありました。`0.4` 程度に緩めることで、「項目の上部が画面に十分入ってきた時点」でアクティブになり、長文でも自然なタイミングで浮かび上がるようになりました。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-08-nk-studio-20-years-inspired
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. 見出しの文字列を変えたい場合は、`init()` 内の `heroTitle.textContent = "20 Years, inspired by people.";` を書き換えるだけです。`splitIntoChars()` が自動的に1文字ずつのspanに分割してくれます。
4. 文字リビールの速さ・間隔を変えたい場合は、CSSの `.split-char` の `transition-delay: calc(var(--i,0) * 26ms)` の `26ms` を調整します。大きくするほど、文字が波のようにゆっくり現れます。
5. タイムラインの項目を増減・編集したい場合は、`STORIES` 配列(`year` / `title` / `text`)を書き換えるだけです。SVGパスと `dot` の位置は `.tl-rail` の実際の高さに自動で追従するため、項目数を変えても調整不要です。
6. ラインの描画される向き・進行の基準(いつ0%でいつ100%か)を変えたい場合は、`initDrawSVGOnScroll()` 内の `total` / `traveled` の計算式を調整してください。
7. 配色を変えたい場合は、`:root` の `--bg` と `--ink` の2値だけを書き換えれば、派生色(`--ink-60` など)も含めて全体の配色が連動して変わります。
