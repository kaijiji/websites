## 何が評価されているか・印象的な点

Steven.com が Awwwards Site of the Day を受賞した理由として、レビューや紹介記事では次のような点が挙げられています。

1. **サイト全体を「1つのオペレーティングシステム」に見立てる構成**
   単なるコーポレートサイトではなく、「Steven.com はオペレーティングシステムです」というコンセプトのもと、事業のカテゴリ(メディア・ベンチャー・イベント・テクノロジーなど)を、それぞれ独立した「場所」として3D空間に配置しています。
2. **Three.js/WebGLによる没入型3D空間へのナビゲーション**
   ユーザーはページをスクロールして情報を読むのではなく、3D空間そのものの中を移動しながら各事業領域を発見していきます。
3. **手描き風のラインと色分けされた経路(pathway)で空間をつなぐ**
   各「場所」は無造作に浮いているのではなく、手描きスケッチのような曲線で結ばれ、その色は行き先のブランドカラーを反映しています。空間に「地図」のような手がかりを与えることで、自由に動き回っても迷わない設計になっています。
4. **パフォーマンスへの配慮**
   豊かな3D表現を保ちながら、アセットの最適化や遅延読み込みによって多くのデバイスで滑らかに動作するよう作り込まれている点も評価されています。

## 使われていると推測される技術・ライブラリ

- **Three.js** による3Dシーンのレンダリング(WebGL)
- カメラをノード間で滑らかに移動させるアニメーション制御(GSAPなどのトゥイーンライブラリ、またはカスタムのイージング処理)
- SVGまたはシェーダーで生成された「手描き風」の接続ライン
- レスポンシブ対応やアセットの遅延読み込みなど、3D体験を軽量に保つための最適化

このデモでは、上記の「仕組み」を学習目的で理解し直すために、**外部ライブラリを一切使わず**、`<canvas>` の2D描画コンテキストの上に自作の透視投影カメラを実装して同じ表現ジャンルを再現しています。Three.jsのような3Dライブラリの内部で実際に何が起きているか(ワールド座標→カメラ座標→スクリーン座標の変換)を、コードとして全部読めるようにしてあります。

## 再現コードの仕組み

`index.html` 1ファイルで完結しています。

### 1. コンテンツ定義(架空のノード)
`NODES` 配列に、架空のプロダクト「ATLAS OS」を構成する7つの領域(HOME・MEDIA・VENTURES・EVENTS・TECHNOLOGY・COMMUNITY・STUDIO)を、3D空間上の座標・色・説明文とともに定義しています。`EDGES` 配列で「どのノードとどのノードをラインで結ぶか」を指定しています(HOMEを中心にしたハブ&スポーク構成 + 関連領域同士の横のつながり)。自分のプロジェクトで使う際は、この2つの配列を書き換えるだけで別のコンテンツに差し替えられます。

### 2. 自前のベクトル演算とパースペクティブカメラ
Three.js を使わない代わりに、`sub`/`add`/`cross`/`dot`/`norm` など必要最小限のvec3演算だけを自分で実装しています。カメラは「視点(`eye`)」と「注視点(`target`)」の2点だけで表現し、毎フレーム以下の手順でワールド座標を画面座標へ変換します。

```js
var fwd   = norm(sub(target, eye));   // 視線方向
var right = norm(cross(fwd, [0,1,0]));// 右方向
var up    = cross(right, fwd);        // 上方向
// ワールド座標 p をカメラ空間の (x, y, z) に変換してから、
// z(奥行き)で割ることで遠近感のある2D座標に投影する
```

これは、Three.jsの `PerspectiveCamera` や `lookAt()` が内部でやっていることを、行列を使わずベクトルの内積・外積だけで書き下したものです。

### 3. カメラを「飛ばす」演出
オービット(俯瞰)モードでは、球面座標(`theta`・`phi`・`radius`)から視点を計算して原点を見下ろし続けます。ノードをクリックすると、目的地を「そのノードの少し手前・少し上」に切り替え、`desiredEyeTarget()` が返す目標値に向かって現在のカメラ位置を毎フレーム`lerp`(線形補間)で近づけます。

```js
camera.eye    = lerpVec(camera.eye,    desired.eye,    0.06);
camera.target = lerpVec(camera.target, desired.target, 0.06);
```

モード切り替え(俯瞰⇔フォーカス)もドラッグ操作による視点回転も、すべて「目標値」と「現在値」の差を毎フレーム縮めるこの一行だけで滑らかにつながります。

### 4. 手描き風の接続ライン
各エッジ(2ノード間の接続)ごとに、直線の中点から法線方向へ「ノードidから決まる疑似乱数」でオフセットさせた制御点を作り、3次ベジェ曲線として48分割でサンプリングしています。同じ曲線をわずかにジグザグさせながら2回重ねて描くことで、鉛筆で描いたような揺らぎのある線に見せています。ラインの色は接続する2ノードの色を線形グラデーションで補間し、「どのカテゴリへの経路か」が色だけでわかるようにしています。

### 5. HUDピン(DOM要素)を3D空間に同期
ノードのラベルは `<canvas>` の中に文字で描く代わりに、通常のHTMLボタン要素として用意し、`project()` で計算した画面座標を毎フレーム `transform: translate3d(x, y, 0)` で反映しています。DOM要素のまま扱うことで、ホバー時の縁取りやクリックのアクセシビリティを、CSSと通常のイベントリスナーだけで自然に実装できます。

### 6. 星屑の背景とパララックス
`mulberry32` という軽量な擬似乱数生成器で座標を決めた260個の点を、視点の回転角に応じてわずかにオフセットさせながら描いています。3D計算をせずに「宇宙にいる感覚」を安価に補強するための工夫です。

## 使い方(コピーしてすぐ使う)

1. `index.html` をそのまま自分のプロジェクトにコピーします(外部ライブラリの読み込み・ビルド設定は一切不要です)。
2. ブラウザで直接開くだけで動作します(ローカルサーバーも不要)。
3. カスタマイズしたいときは、以下を変えるだけで印象が大きく変わります。
   - `NODES` 配列 → ノードの名前・色・3D座標・説明文(パネルに表示されるテキスト)
   - `EDGES` 配列 → どのノード同士をラインで結ぶか
   - `FOCAL`(カメラの画角の強さ)・`orbit.radius` の初期値 → 見え方の広角/望遠感
   - `CAM_LERP`(0.06) → カメラが目標に追いつく速さ。小さくするほど「ゆったり飛ぶ」演出になります
4. ノードをクリックするとカメラがそのノードへ飛び、右側にパネルが開きます。パネル下部の「宇宙全体に戻る」、または背景をクリックすると俯瞰モードに戻ります。

## 注意点・既知の制約

- `<canvas>` の2Dコンテキストのみで3D風の見た目を作っているため、実際の陰影・環境反射・被写界深度などのリアルな3Dレンダリングは行っていません(あくまで「仕組みを理解するための軽量な近似」です)。
- ノードやラインの奥行きによる隠面消去(オクルージョン)は、ノードは深度順(painter's algorithm)で描画順を制御していますが、ラインとノードの前後関係までは厳密には解決していません。
- タッチデバイスでは `cursor:none` によるカスタムカーソルを無効化し、通常カーソルに戻しています。ピンチズームの代わりにドラッグでの視点回転のみ対応しています。
