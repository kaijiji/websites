## 再現コードの仕組みの解説

`index.html` 1ファイルに CSS・JavaScript をすべてインラインで記述しています。実装は、それぞれ独立して他プロジェクトにもコピーできる3つの関数にまとめています。

1. **`initKineticTitle(el, options)` — 文字ばらけ登場タイポグラフィ**
   - 見出し要素のテキストを単語(`.word`)単位でまとめつつ、1文字ずつ `<span class="char">` に分解します。単語のまとまりを保つのは、ブラウザの折り返し(word wrap)で単語の途中に改行が入らないようにするためです。
   - 各文字に `element.animate()`(Web Animations API)で `opacity: 0→1` と `transform: translateY(0.65em) rotate(6deg) → translateY(0) rotate(0)` をかけ、`delay: i * stagger`(文字インデックスに比例した遅延)で1文字ずつ時間差をつけて登場させます。GSAPの`stagger`オプションと同じ考え方を、標準APIだけで再現しています。
   - 登場アニメが終わった文字には `anim.onfinish` で常時ゆらゆらする「idle」アニメーション(CSSの`@keyframes`)を後付けします。位相 `phase = (i * 0.6) % 2π` を負の`animation-delay`として使うことで、文字ごとに揺れのタイミングがずれ、全体が机上の空論的に一斉に動かず自然に見えます。

2. **`initDistortionHover(canvas, options)` — WebGLホバーディストーション**
   - `<canvas>`ごとに独立したWebGLコンテキストを作り、2枚の三角形(`TRIANGLE_STRIP`)でできた全画面クアッドに、オフスクリーン`<canvas>`(2D)で描いたテクスチャを貼り付けます。実サイトの画像は使わず、`options.draw(ctx, w, h)`で好きな絵(このデモではグラデーション+グリッド+ラベル)を焼き込めるようにしています。
   - フラグメントシェーダーで「カーソル位置(`uMouse`)からの距離」に応じたリング状の波 `sin(dist * 34.0 - uTime * 5.0)` を計算し、その波の強さでUV座標をカーソルから離れる方向にずらすことで、水面のような揺れ(ディストーション)を作っています。`smoothstep(0.55, 0.0, dist)`でカーソルから離れるほど効果を弱め、画像全体が揺れすぎないようにしています。
   - ホバーの有無は `uHover`という0〜1のuniformで管理し、目標値へ直接ジャンプさせず `hover += (target - hover) * 0.08` というlerpで毎フレーム近づけることで、マウスが乗った/外れた瞬間にエフェクトが唐突に始まる/終わるのを防いでいます。
   - `gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)`で、Canvas2D(原点が左上)とWebGLのテクスチャ座標系(原点が左下)の違いを補正しています。これを入れないとテクスチャが上下反転して貼り付いてしまう、実装時に実際につまずいた点です(下記「つまずきやすいポイント」参照)。

3. **`createWipeTransition(overlayEl, options)` — ワイプ式ページトランジション**
   - 指定した本数(`stripCount`)の縦ストライプ`<div>`を並べ、それぞれに`transform: scaleY(0)`(非表示)を初期状態として与えます。`transitionDelay`を各ストライプのインデックスに比例させて設定することで、左から順に(または`close()`時は逆順に)せり上がる/せり下がるワイプになります。
   - `open(callback)`を呼ぶとストライプが`scaleY(1)`まで広がって画面を覆い隠し、全ストライプの合計アニメーション時間が経過した後に`callback`(このデモでは詳細パネルの表示)を実行します。`close(callback)`は逆順の遅延で反対方向に再生し、覆いを剥がしてグリッド画面へ戻します。
   - CSSの`transitionend`イベントではなく、ストライプ数×遅延+アニメ時間から計算した`setTimeout`でタイミングを取っています。これは、複数要素の`transitionend`が重複して発火することによるコールバックの二重実行を避けるための単純化です。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-08-artem-shcherbakov-vfx-portfolio
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. 見出しのキネティックタイポグラフィは、他のページでも `initKineticTitle(document.querySelector('h1'))` を呼ぶだけで使えます。`stagger`(文字間の遅延ms)・`duration`(1文字のアニメ時間ms)を`options`で調整できます。
4. WebGLホバーディストーションを別の画像に使いたい場合は、`<canvas>`を用意して `initDistortionHover(canvas, { hoverTarget: 親要素, draw: (ctx, w, h) => { /* ここでctxに画像や絵を描く */ } })` を呼びます。`draw`の中で`ctx.drawImage()`を使えば実際の画像ファイルにも適用できます。
5. ワイプ遷移は `createWipeTransition(overlayEl, { stripCount: 6, stepDelay: 45 })` でストライプ本数と時間差を調整できます。返り値の `open()` / `close()` を任意のタイミング(クリック、ルーティング変更など)で呼ぶだけで組み込めます。
6. ダミーの作品データは `PROJECTS` 配列(`title` / `tag` / `hue` / `desc`)を編集するだけで入れ替えられます。要素数を増減しても `buildGrid()` が自動的に対応します。
7. 配色を変えたい場合は `:root` の `--bg` / `--ink` / `--accent` / `--line` を書き換えるだけで全体に反映されます。

## つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では、対象サイト本体(`artemartemartem.com`)だけでなく `awwwards.com` ・ `cssdesignawards.com` ・ `landing.love` ・ `a1.gallery` などの紹介記事掲載サイト、さらに `web.archive.org` や `r.jina.ai` のようなプロキシ経由の閲覧手段もすべてネットワークポリシーでブロックされていました。そのため検索結果に表示されるスニペット(要約文)のみを根拠に技法を推測しており、実サイトの正確なレイアウト・配色・シェーダーの実装・作品数までは確認できていません。このデモは「公開情報から読み取れる範囲での解釈による再現」であり、実サイトの完全なコピーではありません。
- **WebGLテクスチャの上下反転**: Canvas2Dで描いたテクスチャをそのまま`texImage2D`に渡すと、画像が上下反転して表示されました(見出し文字が反転して読めない状態になっていることをスクリーンショットで確認)。`gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)`を追加することで解決しました。Canvas2Dの座標系(原点が左上、Y下向き)とWebGLのテクスチャUV座標系(原点が左下、Y上向き)が異なることが原因です。
- **ソフトウェアWebGLの警告**: サンドボックス環境(GPU非対応のヘッドレスブラウザ)で検証すると「Automatic fallback to software WebGL has been deprecated」という警告が出ますが、これは検証環境固有の制約であり、通常のブラウザ(GPU利用可能な環境)では発生しません。実装上の問題ではないため対処は不要と判断しました。
- **ワイプ遷移のタイミング管理**: 各ストライプの`transitionend`を個別に監視すると、ストライプ数分イベントが発火してコールバックが複数回実行されてしまう問題がありました。ストライプ数×遅延+アニメーション時間から総所要時間を計算し、`setTimeout`を1回だけ仕掛ける方式に変更することで、コールバックの二重実行を防いでいます。
