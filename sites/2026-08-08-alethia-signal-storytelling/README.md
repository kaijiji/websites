# SIGNAL / TRUST — 環境データ・ストーリーテリング表現の再現デモ

## 参照元サイト

- **サイト名**: Alethia
- **URL**: https://www.alethia.earth/
- **受賞歴**: Awwwards *Site of the Day*(2026年8月6日、スコア 7.34/10)。制作は ++hellohello、Pablo Picart、SEB®、Ismael Martínez。Animation・Scrolling・Storytelling・Interaction Design のカテゴリで評価されています。Alethia は、大気センサーとブロックチェーンを組み合わせて温室効果ガス(GHG)の削減・吸収量を継続的に計測・検証する「環境インテリジェンス・プラットフォーム」です。

> **本フォルダのコードは学習目的のオリジナル実装です。** 上記サイトの実際のソースコード(HTML/CSS/JS)・画像・映像・テキストコピーは一切取得・参照・複製していません。また、このセッションのネットワーク環境では `alethia.earth` 本体および `awwwards.com` への直接アクセスが制限されていたため、実サイトを直接閲覧してはいません。Awwwards の受賞ページ掲載情報(配色コード・カテゴリ・使用ツール・スコア・クレジット)や、それを紹介する記事の検索結果から読み取れる「どんな表現技法が使われているか」だけを手がかりに、見た目・文言・コードすべてをゼロから独自に設計・実装しています。統計数値やコピーはすべて演出用のダミー値・架空の文言です。

## 評価されている理由・印象的だった点

Alethia のサイトは、「複雑な環境データを、誰が見ても明快で信頼できるものに感じさせる」というブランドの目的そのものを、コンテンツ・ビジュアル・インタラクションが一体となったUIに落とし込んでいる点が評価されています。

- ダークグリーン(`#0F1F10`)とライトなイエローグリーン(`#C6F19D`)だけに絞った、潔い2トーン配色。環境・信頼性というテーマを、装飾を足すのではなく色数を削ることで表現している
- ヒーロー・スクロール中・フッターと、映像を要所要所で使ったスクロール連動のストーリーテリング構成
- Animation / Scrolling / Storytelling / Interaction Design の4カテゴリで評価されるほど、「動き」そのものが情報を伝える手段として設計されている
- 「測定→検証→報告→信頼」という抽象的なプロセスを、視覚的な進行(タイムラインやシグナルの可視化)として体感させる見せ方

## 使われている技術・ライブラリの推測

Awwwards の受賞ページに掲載された情報として、以下が確認できました。

- **Figma / Framer** — デザイン・実装のツールとして明記されています。Framer は Motion(旧 Framer Motion)ベースのアニメーション機能を内蔵しているため、スクロール連動アニメーションや映像の再生制御も、それらの機能を使って組まれていると推測されます。

このデモでは、Framer のようなノーコード/ローコードツールを使わず、**外部ライブラリに依存しないバニラJavaScript**で「スクロール位置に応じて何かが進行していく」表現の仕組み自体を再現しています。実サイトが映像(動画スクラビング)で見せている可能性がある部分を、このデモでは `<canvas>` に描く「計測シグナルの波形」に置き換えて表現しました。

## 再現コードの仕組みの解説

`index.html` 1ファイルに CSS・JavaScript をすべてインラインで記述しています。実装は、それぞれ独立して他プロジェクトにもコピーできる小さな関数の集まりとして書かれています。

1. **`getScrollProgress(spacerEl)` — ピン留めスクロールの進捗計算(共通基盤)**
   外側に高さ(`280vh`や`320vh`)を確保した「spacer」要素の `getBoundingClientRect().top` から、その要素が画面を通過する進捗を 0〜1 の値として計算します。内側の要素を `position: sticky` で画面に固定しつつ、この進捗値を使って中身のアニメーションを進める——という「ピン留めスクロール」演出の土台になる関数で、このデモの2つのセクション(シグナル波形・検証タイムライン)で使い回しています。

2. **`initSignalSection()` — スクロール連動のシグナル波形 + カウントアップ**
   あらかじめ正弦波を複数重ねてノイズを加えた「疑似計測データ」の配列を生成しておき、`getScrollProgress()` の値に応じて、その配列を先頭から何点分 canvas に描画するかを増やしていきます。結果として、スクロールするほど波形が左から右へ「描き進む」ように見えます。同時に、同じ progress 値を使って中央の数値カウンターを 0 から目標値まで動かし、下部の進捗バーの幅も更新します。1つの progress 値から複数の表現を同時に駆動するのがポイントです。

3. **`initVerificationTimeline()` — 段階的に点灯する検証タイムライン**
   「MEASURE → VERIFY → REPORT → TRUST」の4ノードを、ステップ数で等分した進捗の閾値と比較し、スクロール位置がその閾値を超えたノードから順番に `is-active` クラスを付与して点灯させます。ノード間をつなぐ線(`.timeline-fill`)の幅も同じ progress 値で更新しているため、「線が伸びながらノードが順に光る」という一体感のある演出になります。

4. **`initCountUpCards()` — 画面に入ったら動く統計カード**
   `IntersectionObserver` でカードが画面に入ったタイミングを検知し、その瞬間から `requestAnimationFrame` で 0 から目標値まで ease-out で数字を増やします。ページ全体のスクロールに常時反応する `initSignalSection()` とは違い、こちらは「一度画面に入ったら1回だけ再生する」タイプのアニメーションです。同じスクロール駆動の演出でも、常時追従型と一回再生型の2種類を使い分けている点を実装で示しています。

5. **`splitIntoLines()` / `splitIntoWords()` / `observeReveal()` — マスクリベール見出し**
   見出しを行・単語ごとに `<span>` へ分解し、CSS変数 `--i`(出現順インデックス)を注入します。CSS側は `transition-delay: calc(var(--i) * 数値)` を指定するだけで、「順番にせり上がる」演出になります。段落は `IntersectionObserver` で画面に入った瞬間に `is-in` クラスを1回だけ付与して発火させます。

### つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では `alethia.earth` や `awwwards.com` への直接アクセスがネットワークポリシーでブロックされていました。そのため検索結果の要約情報(配色コード・カテゴリ・使用ツール・スコアなど)のみを根拠に設計しています。実サイトの正確なインタラクション詳細(映像の演出内容やタイミングなど)までは確認できていないため、このデモは「公開情報から読み取れる範囲での解釈」であり、実サイトの完全な再現ではありません。
- **`getBoundingClientRect()` を毎フレーム呼ぶコスト**: スクロール量からアニメーションを駆動する実装では、`scroll` イベントではなく `requestAnimationFrame` ループの中で `getScrollProgress()` を呼ぶ設計にしています。スクロールイベントは短時間に大量発火するため、rAFループで「今の状態」を毎フレーム読みにいく方が、余計なイベントスロットリング処理を書かずに済みます。
- **カウントアップの二重発火**: `initCountUpCards()` では `IntersectionObserver` の `io.unobserve(entry.target)` を呼び忘れると、画面の出入りのたびにアニメーションが再発火してしまいます。「1回だけ再生」させたい演出では、発火直後に観測を止めることを徹底しています。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-08-alethia-signal-storytelling
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. シグナル波形のカウンター目標値は `initSignalSection()` 呼び出し時の `target` 引数を変更するだけで調整できます。
4. 検証タイムラインのノード数・ラベル・説明文は `initVerificationTimeline()` の `steps` 配列を増減・変更するだけで調整できます(ノードの点灯閾値はステップ数から自動計算されます)。
5. 統計カードの枚数・数値・ラベルは `initCountUpCards()` の第2引数の配列を書き換えるだけで反映されます。
6. 配色を変えたい場合は、`:root` の `--bg` / `--fg` / `--accent` の3つのCSS変数を書き換えるだけで、波形の色以外は全体に反映されます(波形は `initSignalSection()` 内の `ctx.strokeStyle` / `ctx.fillStyle` も合わせて変更してください)。
