## 何が評価されているか・印象的な点

Active Theory V6 が繰り返し評価されているのは、次のような点です。

1. **カーソルが「自分だけのもの」ではない**
   画面の上端・下端から自分のカーソル位置まで発光するチューブ状の線が伸びますが、これは自分だけでなく同時にサイトを見ている他の来場者のカーソルもリアルタイムに共有・描画される、という仕組みになっています。1人で見ているはずのポートフォリオサイトに、他人の気配が同時に映り込むという体験そのものが独創的です。
2. **黒背景でWebGLの発色を最大化する潔さ**
   ほぼ純黒（#0B0B0B前後）の背景に絞ることで、ネオンのようなチューブやカラフルなプロジェクト映像の発色だけが際立ちます。
3. **ホバー1つで生まれる「ラックフォーカス」感**
   プロジェクト一覧でカードにカーソルを乗せると、そのカードだけが手前に浮かび上がって拡大・プレビュー動画が再生される一方、隣接するカードはわずかに沈んで暗くなります。カメラのピント（フォーカス）が奥から手前へ移動したかのような、映画的な視差を一瞬のホバーだけで演出しています。

## 使われていると推測される技術・ライブラリ

- **WebGL / 独自レンダリングエンジン「Hydra」**（Active Theory が社内開発している、ノードベースGUIも備えたフレームワーク）によるフルスクリーンの3Dシーン描画
- **WebSocket 等によるリアルタイム通信**で、来場者同士のカーソル座標を共有する「マルチプレイヤー」的な仕組み
- GSAP など、ホバー時のスケール・明度変化をなめらかに補間するアニメーションライブラリ
- Draco圧縮・遅延読み込みなど、リッチな表現と表示速度を両立させるための最適化

このデモでは、上記のうち**外部ライブラリを一切使わず**、Canvas 2D APIとバニラJavaScriptだけで「上下端からカーソルまで伸びる発光チューブ」と「隣接カードが沈むホバーグリッド」という2つの仕組みを再現しています。またサーバー通信は行わず、自律的に動き回る座標を使って複数人のカーソルが同時に存在する見た目だけを疑似的に再現しています。

## 再現コードの仕組み

`index.html` 1ファイルで完結しています。

### 1. `TubeCursor` クラス（PART 1）
1人分のカーソル（自分／疑似的な他の来場者）を表すクラスです。

- `update(dt)`: 目標座標（マウス位置、またはゴーストの自律運動の目標）に対して `this.x/y` を `lerp`（線形補間）で追従させます。自分のカーソルは追従係数を大きく（機敏に）、ゴーストは小さく（ゆったり）することで質感を書き分けています。
- 上下の「アンカー」座標（`topAnchorX` / `bottomAnchorX`）もカーソル本体よりさらに遅れて追従させることで、チューブがしなるようなオーガニックな揺れを生んでいます。
- `drawTube()`: 画面上端 → カーソル位置 → 画面下端 を2本の `quadraticCurveTo` でつなぎ、太さ・透明度を変えた3本のストローク（太くて薄い線 → 細くて濃い線）を重ね書きすることで、ネオン管のような「にじみ」を安価に表現しています。`shadowBlur` も併用してさらに発光感を強めています。
- `drawTrail()`: カーソル自身が直近何フレーム分か通った座標を配列で保持し、だんだん透明・細くなる線で結ぶことで、彗星の尾のような軌跡を追加しています。

```js
this.x += (this.tx - this.x) * smooth; // 目標へ少しずつ近づく
this.trail.unshift({ x: this.x, y: this.y }); // 軌跡を先頭に追加
if (this.trail.length > TRAIL_LENGTH) this.trail.pop(); // 古い点を捨てる
```

### 2. 疑似「他の来場者」（ゴースト）
`GHOST_COUNT` 人分の `TubeCursor` を、`wander(t)` メソッドでサイン波を組み合わせた軌道上に自律的に動かしています。実際のマルチプレイヤー通信（WebSocketサーバーとの座標共有）は行っていませんが、「自分以外の誰かが同時にこの画面を見ている」という体験の雰囲気だけを、依存ゼロのフロントエンドだけで再現しています。自分のプロジェクトで本物のマルチプレイヤー化をしたい場合は、`ghosts` 配列の座標更新部分を WebSocket などから受け取った座標に差し替えるだけで移行できます。

### 3. ラックフォーカス・ホバーグリッド（PART 2）
プロジェクトカードを `PROJECTS` 配列から動的に生成し、各カードに `mouseenter` / `mouseleave` を設定しています。

```js
function setHover(activeIndex) {
  tiles.forEach((el, i) => {
    el.classList.toggle('is-hovered', i === activeIndex);
    el.classList.toggle('is-dimmed', activeIndex !== null && i !== activeIndex);
  });
}
```

ホバーされたカード自身には `is-hovered`（拡大・明るく・手前に浮く）、それ以外の兄弟カードには `is-dimmed`（わずかに沈む・暗くする）というクラスを付け外しするだけです。実際の見た目の変化はすべてCSSの `transition` に任せているため、JavaScript側はクラスの切り替えだけを担当するシンプルな構成になっています。

## 使い方（コピーしてすぐ使う）

1. `index.html` をそのまま自分のプロジェクトにコピーします（外部ライブラリの読み込み・ビルド設定は一切不要です）。
2. ブラウザで直接開くだけで動作します（ローカルサーバーも不要）。
3. カスタマイズしたいときは、以下の値を変えるだけで印象が大きく変わります。
   - `GHOST_COUNT`（PART 1 冒頭）→ 疑似的な「他の来場者」の人数（0にすれば自分のカーソルだけになります）
   - `HUE_SPEED` / `TRAIL_LENGTH` → チューブの色が変わる速さ／軌跡の長さ
   - `passes` 配列（`drawTube()` 内）の `width` / `alpha` → チューブの太さ・にじみ具合
   - `PROJECTS` 配列（PART 2）→ カードの枚数・ラベル・グラデーション色
   - `.tile` の CSS `transition` の秒数・`cubic-bezier` → ホバー時の沈み込み・拡大の速さや質感
4. 他のページに移植する場合は、`#tube-canvas` を任意のセクションに配置し、`hero` 変数が指す親要素（`canvas.parentElement`）のサイズに合わせてキャンバスが自動リサイズされる点だけ確認してください。

## 注意点・既知の制約

- 本物のマルチプレイヤー機能（他の閲覧者との座標共有）は再現していません。ゴーストカーソルはすべてクライアント側の自律運動によるダミーです。
- タッチデバイスでは `touchmove` でカーソル位置を更新していますが、上下2方向にチューブが伸びる都合上、画面が小さいスマートフォンでは視認性が下がることがあります。
- グリッドのプレビュー画像・動画は用意していないため、CSSグラデーションのみで質感を表現しています。実プロジェクトでは `.tile-bg` の代わりに `<video>` や `<img>` を差し込んで発展させてください。
