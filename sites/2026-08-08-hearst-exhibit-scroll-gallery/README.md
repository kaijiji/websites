# REVEAL PLATES — スクロール連動WebGLシェーダー画像リビール & FLIPライトボックス 再現デモ

## 参照元サイト

- **サイト名**: Hearst Exhibit 2026 — 「ELLE & Esquire, The New Hollywood Photography Exhibition」(制作: OSMOS PRO)
- **URL**: https://www.hollywoodexhibit2026.com/
- **受賞歴**: Awwwards *Site of the Day*(2026年8月2日、Developer Award付き。総合スコア 7.27/10 / Design 6.9 / Usability 7.4 / Creativity 7.5)。ELLEとEsquireが共同開催した、ハリウッドを撮り続けてきた40年分のアーカイブ写真展を紹介するギャラリー/展覧会サイトです。

> **本フォルダのコードは学習目的のオリジナル実装です。** 参照元サイトの実際のソースコード(HTML/CSS/JS)・写真・映像・テキストコピーは一切取得・参照・複製していません。また、このセッションのネットワーク環境では `hollywoodexhibit2026.com` および `awwwards.com` 本体への直接アクセスがネットワークポリシーでブロックされていたため、実サイトを直接閲覧してはいません。検索結果に表示されたAwwwardsの受賞ページ情報(カテゴリ・使用技術スタック・スコア・配色傾向)や、それを紹介する記事の要約、および同種の技法を解説した公開チュートリアル記事の要約だけを手がかりに、見た目・文言・コードすべてをゼロから独自に設計・実装しています。作品名・年号・撮影地名などはすべて架空のダミーです。

## 評価されている理由・印象的だった点

検索結果から確認できた情報によると、Hearst Exhibit 2026は「写真そのものを主役にした、静かで洗練された見せ方」が評価されています。

- ほぼ2色構成のミニマルな配色で、写真の色や質感を邪魔しないニュートラルな器として画面を設計している
- スクロール連動のインタラクション、ギャラリーらしいレイアウト、タイポグラフィ、マイクロインタラクションが評価軸として挙げられており、「動きのための動き」ではなく写真の見せ方に奉仕する演出が特徴
- WebGLとGSAPを使ったスクロール操作・遷移が使われており、Photography/Gallery系のAwwwards受賞サイトに共通する「画像がスクロールで少しずつ現れる」体験を持つ
- Developer Awardを受賞しており、単なる見た目だけでなく実装の作り込みも評価されている

## 使われている技術・ライブラリの推測

検索結果(Awwwardsの受賞ページ情報の要約、および同種のWebGLギャラリー実装を解説した公開チュートリアル記事の要約)から、以下の技術的な特徴が使われていると推測しました。

- **WebGL** — 画像をテクスチャとして描画し、シェーダーで加工した状態からスクロールに応じて本来の見た目へ変化させる、という技法にはWebGL(Three.jsなどのラッパー経由の可能性が高い)が使われていると推測されます
- **GSAP** — スクロール位置の監視やタイミング制御に使われる定番ライブラリ
- 同種の「スクロールで画像がシェーダー越しに現れ、クリックで大きな詳細表示へシームレスに繋がる」ギャラリー実装を解説した公開チュートリアル記事(Three.js・GSAP・ページ遷移ライブラリを組み合わせる手法)が存在しており、これがHearst Exhibit 2026のようなAwwwards受賞のギャラリー系サイトで広く使われている実装パターンであることが確認できます

このデモでは、Three.jsやGSAPといった外部ライブラリを一切使わず、**依存ゼロのバニラJavaScript + 生WebGL**で「同じ体験の仕組み」を再現しています。ライブラリなしで書くことで、「スクロール位置→シェーダーのuniform値」「クリック→拡大アニメーション」がそれぞれ何十行程度のコードでできることを実感できるようにしています。

## 再現コードの仕組みの解説

`index.html` 1ファイルに CSS・JavaScript をすべてインラインで記述しています。実装は3つの独立した仕組みに分かれており、それぞれ他プロジェクトにもそのままコピーできます。

1. **`createPlateRenderer()` / シェーダー — グレースケール→カラーのスクロールリビール**
   図版(`.plate`)ごとに小さな `<canvas>` を1枚ずつ生成し、それぞれに独立したWebGLコンテキストを持たせています。フラグメントシェーダーの中で、テクスチャの色を輝度(`dot(rgb, vec3(0.299,0.587,0.114))`)からグレースケール化したものと、元のフルカラーを `u_progress` という0〜1のuniform変数で `mix()` しています。さらに `smoothstep()` を使い、progressの値に応じて画面下から上へ向かう柔らかい境界線(ワイプ)で色が「染み込んでいく」ように見せています。
   `u_progress` は、その図版の `getBoundingClientRect().top` がビューポートのどのあたりにあるかを毎フレーム計算して求めています(`computeProgress()`)。IntersectionObserverの発火/非発火(0か1)ではなく、`requestAnimationFrame` ループで連続的な値を計算しているため、スクロール量に完全に同期したなめらかな変化になります。

2. **`makePlateTexture()` — 実在の写真を使わない、生成グラデーション「疑似写真」**
   実サイトの著作権を侵害しないよう、実在の写真データは一切使っていません。代わりに `<canvas>` の2D APIで、線形グラデーション+複数の柔らかい光のブロブ(放射状グラデーション)+粒状ノイズ(フィルムグレイン風)+ビネット(周辺減光)を重ねて、「写真の版」らしい質感を持つ画像をその場で生成しています。`mulberry32()` という小さなシード付き疑似乱数生成器を使っているため、リロードしても毎回同じ見た目になり、デモとして安定します。自分のプロジェクトで実際の写真を使いたい場合は、この関数が返す `<canvas>` を `<img>` や別の画像ソースに差し替えるだけで、シェーダーによるリビール効果はそのまま使えます。

3. **`openLightbox()` / `closeLightbox()` — FLIP法によるクリック拡大**
   サムネイルをクリックすると、そのまま画像が「持ち上がって」画面中央に大きく表示される演出は、**FLIP(First・Last・Invert・Play)**という定番のアニメーション技法で実装しています。
   - **First**: クリックされた図版の現在位置(`getBoundingClientRect()`)を記録
   - **Last**: ライトボックス要素を最終的な表示位置(画面中央・大きいサイズ)に直接配置してしまう
   - **Invert**: LastからFirstへ戻すための `translate() scale()` を計算し、`transition: none` の状態で即座に適用する。これにより見た目上は一瞬でサムネイルの位置に戻る
   - **Play**: 次のフレームで `transition` を有効にし、`transform` を `translate(0,0) scale(1,1)` (=Lastの状態)に戻す。ブラウザがこの変化を自動的に補間するため、「サムネイルの位置からそのまま滑らかに拡大する」動きになる
   この方法の利点は、**手動でrequestAnimationFrameループを回して座標を毎フレーム計算する必要がなく、CSSのtransitionだけでGPUアクセラレーションの効いたスムーズなアニメーションになる**ことです。閉じるときも同じ関数を逆方向に使っているだけです。

4. **`initSplitTitleReveal()` — 見出しの行リベール**
   見出しを `<span class="line"><span>テキスト</span></span>` という二重構造にし、外側 `overflow:hidden` で切り取りながら内側spanを `translateY(115%)` → `translateY(0)` に動かすことで、行ごとに下から立ち上がるリベールを作っています。

### つまずきやすいポイント(実装時に直面した問題と対策)

- **ネットワーク制限で実サイトを直接見られなかった**: このセッションの実行環境では `hollywoodexhibit2026.com` や `awwwards.com` への直接アクセスがネットワークポリシーでブロックされていました。そのため検索結果の要約情報(カテゴリ・技術スタック・スコア・受賞歴・関連チュートリアル記事の要約)のみを根拠に設計しています。実サイトの正確な配色・レイアウト・アニメーションの数値までは確認できていないため、このデモは「公開情報から読み取れる範囲での解釈による再現」であり、実サイトの完全なコピーではありません。
- **FLIPの `Invert` 計算で `transform-origin` を意識し忘れると位置がズレる**: `translate()` と `scale()` を同時に使う場合、`transform-origin` が `center`(デフォルト)のままだと拡大縮小の基準点がズレて計算が合わなくなります。このデモでは `transform-origin: 0 0`(左上基準)に固定した上で、`tx = origin.left - target.left` のように「左上座標の差分」だけで計算する方式にすることで、シンプルな式のまま正しく動くようにしています。
- **`Invert` の状態を一度確実に描画させる必要がある**: `transition: none` にして `transform` を変更した直後に `transition` を有効化してしまうと、ブラウザが2つの変更をまとめて処理し、アニメーションが発生しないことがあります。対策として、`transform` を設定した直後に `void lightbox.offsetWidth` で強制的にレイアウトを再計算させ(リフローの強制)、ブラウザに一度その状態を確定させてから次のフレームで `transition` を有効にしています。
- **図版ごとに個別のWebGLコンテキストを使う設計にした**: 実サイトのような大規模ギャラリーでは、パフォーマンスのために1枚の大きな `<canvas>` の上に全図版を「板」として描画し、DOM要素とその位置を同期させる手法が使われている可能性が高いです。今回は図版数が少ない学習用デモであるため、シンプルさを優先して図版ごとに独立した小さな `<canvas>`(＋WebGLコンテキスト)を持たせる設計にしています。数百枚規模のギャラリーを作る場合は、コンテキスト数の上限(ブラウザごとに大体16個前後)に注意し、1枚の共有canvasに描画する設計へ変更することをおすすめします。

## 使い方(コピーしてすぐ使う手順)

1. `index.html` を1ファイルごと自分のプロジェクトにコピーします(外部ライブラリ・画像・フォントへの依存は一切ありません)。
2. そのままダブルクリックで `file://` として開いても動作します。ローカルサーバー経由で見る場合は以下のようにします。

   ```bash
   cd sites/2026-08-08-hearst-exhibit-scroll-gallery
   python3 -m http.server 8080
   # ブラウザで http://localhost:8080 を開く
   ```

3. 図版の数・タイトル・年は `<section class="archive">` 内の `.plate` 要素をコピー/削除するだけで増減できます。`data-title` / `data-year` を書き換え、`.cap-index` / `.cap-title` / `.cap-year` のテキストも合わせて書き換えてください。`.plate` であれば自動的にリビール演出とクリック拡大が有効になります。
4. 配色は `PALETTES` 配列(`[グラデーション開始色, 終了色]` のペアの配列)を書き換えると変わります。図版の数がパレット数より多い場合は自動的に先頭から繰り返し使われます。
5. 実際の写真を使いたい場合は、`makePlateTexture()` の戻り値を、あらかじめ読み込んでおいた `<img>` 要素や `Image` オブジェクトに差し替えてください(`renderer.setTexture(実画像)` を呼ぶだけでシェーダー側の処理はそのまま使えます)。
6. スクロールリビールの効き方(どのタイミングで完全に色がつくか)は `computeProgress()` 内の `start` / `end` の係数(ビューポート高さに対する割合)で調整できます。
7. ライトボックスの表示サイズは `getDetailRect()` の中の `Math.min(vh * 0.82, 780)` などの数値を変更すると調整できます。
